## Security boundaries exercised

The host supplies principal, meeting, opted-in prior meetings, approved folders and snapshot. Model tools cannot override these values or invoke shell/write/grant operations. Every retained read uses one coherent SQLite view for policy plus content and rechecks access on each fresh call, including old snapshots, exports, private history, checkpoints, summaries, MCP and model tool reads. Generation rechecks after a slow provider returns. Additional provenance validation checks retained text, offset, line origin, hash, revision, kind, meeting and path before returning citations.

Late ASR segments, final rewrites and explicit project refreshes create retained versions; old snapshots keep exact IDs. Private history also uses a pinned monotonically assigned turn watermark, not merely timestamps. Prior answers from an unselected/revoked scope are not reused. Shared generation excludes all private turns, project files and user supplements. Trace exports filter snapshot metadata by the current principal and ACL.

Project tests cover traversal, symlink escape, secret-name/binary/oversize exclusions, runtime overlap and unchanged source hashes. Filename/type exclusions are a conservative filter, not a guarantee that arbitrary source code contains no secrets. The trusted local OS/config boundary remains explicit; no external login system or malicious-OS-process isolation is claimed. Native Windows junction escape/root rejection was subsequently verified at c763c14; native symlink permission was unavailable and that test skipped. Broader case/UNC/reparse behavior still requires target-platform checks. See [junction evidence](../results/windows-junction.json).

## Upstream and compatibility

24 vendored implementation/SQL files match the pinned upstream bytes. Existing capture backends, Faster Whisper, storage, evidence framing and LiteLLM helper are used in running paths. Added unmodified native assistant/service/repository files are used by the baseline harness. MCP wrapping, the minimal CPU/path seams and the common native transport bridge are explicitly distinguished from unchanged upstream code; MIT attribution is packaged. The upstream checkout itself remains unchanged.

The native runner does **not** instantiate the full desktop app, native hybrid RAG, native model engine or OS credential store. It uses the original service's session, publish, direct-question, memory, parsing and persistence behavior with a small SummaryEngine transport bridge and synthetic meeting/transcription parent rows. This is a reproducible native-service comparison path, not a claim that the entire upstream desktop baseline was measured.

Missing provider usage stays unknown: the adapter rejects SDK-generated stream token estimates and ambiguous all-zero non-stream usage, keeping cost null. Configuration requires actual JSON booleans for upload/streaming opt-in and validates resource/price bounds.

Wire fixtures follow the official [OpenAI Chat Completions streaming contract](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events) and [Anthropic Messages streaming contract](https://platform.claude.com/docs/en/build-with-claude/streaming). LiteLLM performs protocol translation; the adapter assembles bounded normalized results and the host validates tool arguments. Compatibility is asserted for these tested shapes, not every vendor/model or reasoning/audio response type.
